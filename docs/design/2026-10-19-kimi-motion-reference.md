## Kimi 实际观察

浏览范围包含 `/`、`/land-on`、滚轮进入的 `/about-us` 及后续章节。桌面视口为 1440 × 900；另检查了 390 × 844 的窄屏布局。

| 观察项 | 实际行为 | 对个人站设计的意义 |
| --- | --- | --- |
| 整屏舞台 | 主容器保持一屏高，场景前进时 `scrollY` 仍为 0；内容在舞台内部切换 | 应把它理解为场景切换体验，不能仅给普通长页面增加淡入动画 |
| 纵深推进 | 开场框架放大，原文案淡出并向上下错开，中心月体逐渐成为主体 | 纵深来自尺度、前后景和时序的配合 |
| 过渡节奏 | 滚轮或方向键触发一段过渡，随后停稳；短时间再次输入可能被过渡锁阻止 | 不应默认实现成滚动距离与动画进度严格一一对应 |
| 章节滑入滑出 | `/land-on` 到介绍章节及后续切换中，观察到 `clip-path` 遮罩边界扫过视口，前后场景交接 | 遮罩、滑移与纵深可以分别承担不同转场任务 |
| 内容分层 | 背景持续呈现，界面文字和入口按独立进度出现或退出 | 阅读内容应有稳定停留状态，避免所有元素同时运动 |
| 顶部导航 | 本次桌面各场景采样中导航上沿保持 y=0，高度 60px | 导航应独立于内容转场层，持续可用 |
| 反向浏览 | 已实际验证 `ArrowUp` 从 land-on 返回上一幕，进度反向回退 | 应在设计中考虑返回路径和过渡期间的输入处理 |
| 移动布局 | 390px 宽时导航收为菜单按钮，三个入口纵向排列，未发现横向溢出 | 移动版需要重新构图，不能只缩小桌面画布 |

观察到的纵深不等于所有部分都使用真实三维场景。land-on 的两个 Canvas 在本次访问中均取得已有的 2D 上下文；公开脚本中也能看到首屏缩放和月体逐像素绘制。个人站应先确定要表现的空间关系，再选择 Canvas、CSS 或 Three.js。

## 待讨论的迁移建议

以下是建议，不作为用户已经批准的需求：

- 顶部导航独立于场景层，允许访客直接到达目标内容。
- 关键视觉和章节交接使用纵深与滑入滑出；长段经历、项目说明在停稳状态阅读。
- 为过渡安排清楚的“退出、交接、进入、停稳”阶段，避免各层同时出现。
- 采用独立的个人视觉主题，动效机制与颜色、字体、图形题材分别决策。
- 移动版与减少动态效果模式需要独立方案，之后再确定降级方式。
- 现有导航文字、章节锚点、项目内容和事件名称的调整，留到信息架构讨论中明确。
